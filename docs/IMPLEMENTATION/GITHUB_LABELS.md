# GitHub Labels

This document lists the labels to be created in the GitHub repository for issue tracking and pull request management.

| Name | Purpose | Example Usage |
| :--- | :--- | :--- |
| `frontend` | Issues and PRs related to the frontend interface and logic. | A bug in a React component, or a new UI feature. |
| `backend` | Issues and PRs related to the backend logic, API, and core system. | Modifying the API, updating backend services. |
| `runtime` | Issues related to the core runtime execution environment. | Optimizing the execution engine or fixing a runtime error. |
| `planner` | Issues related to the AI planning subsystem. | Improving the planning logic or fixing a plan generation bug. |
| `worker` | Issues related to worker agents or background tasks. | Adding a new worker capability, fixing a worker crash. |
| `supervisor` | Issues related to the supervisor subsystem managing agents. | Enhancing supervisor oversight or fixing delegation issues. |
| `healing` | Issues related to self-healing mechanisms and error recovery. | Improving automatic error recovery from exceptions. |
| `database` | Issues related to database schema, queries, and data storage. | Adding a new table, optimizing a query. |
| `documentation` | Improvements or additions to documentation. | Updating the README, adding API docs. |
| `testing` | Issues focused purely on testing infrastructure or writing tests. | Adding unit tests, fixing a flaky integration test. |
| `bug` | Something isn't working as expected. | The login button is not responding. |
| `enhancement` | New feature or request. | Adding a dark mode theme. |
| `blocked` | Issue cannot be worked on until another issue or external factor is resolved. | Waiting for an external API key or another PR to merge first. |
| `priority-high` | Critical issues that need immediate attention. | System crash in production, critical security vulnerability. |
| `priority-medium` | Important issues to be fixed in the normal development cycle. | Standard bug fixes or planned features. |
| `priority-low` | Nice-to-have features or minor fixes that are not urgent. | Small UI tweaks, minor typo fixes. |
| `good-first-issue` | Good for newcomers to the project. | Simple typo fixes, basic component creation. |
